# Source Fact Register

This register is the canonical fact bank for fact-backed tutorials and quiz questions.
Facts here are technical training anchors, not legal, regulatory, accounting, privacy,
compliance, or model-risk advice.

Tutorials and challenge questions should reference these fact IDs when they teach or
test an external rule, product behavior, or platform constraint. A released question
should not ask for a vague opinion when a source-backed fact can be tested instead.

## Authoring Contract

- Every fact-backed tutorial step should cite one or more `FACT-*` IDs.
- Every quiz question about regulation, platform behavior, data privacy, storage, or
  BI tooling should cite one or more `FACT-*` IDs in the manifest or lesson notes.
- The prompt should ask about a concrete consequence of the source fact.
- The explanation should identify the source fact, the learner action, and the
  specific mistake the wrong answers represent.
- If a source changes, update the fact first, then update dependent tutorials,
  manifests, solution fixtures, and Playwright flows.

## Planned Tutorial Usage

- Orientation should use `FACT-DUCKDB-WASM-BROWSER`, `FACT-WEB-LOCALSTORAGE-PERSISTENCE`,
  `FACT-WEB-COOKIE-SYNC`, and `FACT-GDPR-DATA-MINIMISATION`.
- Dataset inspection should use `FACT-GDPR-PERSONAL-DATA`,
  `FACT-GDPR-DATA-MINIMISATION`, and `FACT-FGDB-100K-PER-DEPOSITOR-PER-BANK`.
- Fanout and metric-grain lessons should use `FACT-FGDB-100K-PER-DEPOSITOR-PER-BANK`,
  `FACT-BIGQUERY-LOGICAL-VIEW`, and `FACT-BIGQUERY-VIEW-SCOPE`.
- Looker Studio evidence should use `FACT-LOOKER-STUDIO-DATA-SOURCE`,
  `FACT-LOOKER-STUDIO-CALCULATED-FIELD-SCOPE`,
  `FACT-LOOKER-STUDIO-CREDENTIALS`, and `FACT-BIGQUERY-VIEW-LIMITATIONS`.
- BI operations lessons should use `FACT-DORA-ICT-RISK-FRAMEWORK`,
  `FACT-DORA-ICT-IDENTIFICATION`, and `FACT-EBA-DPM-VALIDATION-RULES`.
